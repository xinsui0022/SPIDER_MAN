# 所有文件如何理解

| 路径 | 用途 |
| --- | --- |
| `CoopSync/src/` | 自研协调器、协议、TCP、抽象适配桥、原生只读DLL源码 |
| `CoopSync/tests/` | 核心、协议、网络集成、假后端、原生控制与分析检查 |
| `CoopSync/tools/` | 任务观察、联合录制、加载控制、严格分析工具 |
| `CoopSync/research/` | 固定hash静态探针、反汇编证据、只读probe与接口报告 |
| `CoopSync/logs/` | 原始实录、分析、测试结果、稳定备份；按日期解释 |
| `CoopSync/build/` | 历史/当前编译产物，可重新构建；不是安装即联机的发布包 |
| `序章修复调查/` | 老门故障、存档差异、SMT/GameNet调查、原版/SMT对照、DoorStep源码和只读helper |
| `HeiheiSMT0.5.1/`及zip | 原有第三方MOD参考、审计材料；没有新增剧情/敌人同步实现 |
| `哥哥安装候选包_20261006/`及zip | 早期原MOD安装候选与说明，保留历史，不当成自主成品 |
| `穿门助手候选_20261007*/`及zip | 本地DoorStep移动实验；不能代替门/碰撞复制 |
| `联机需求与进度核对_20261010.md` | 早期完整需求与门故障记录，包含随后更新 |
| `交接资料/` | 最新权威状态、接手入口、文件清单和原构建留档 |

为避免破坏历史工具的相对路径，保留原目录而非批量移动。大文件经Git LFS取回，文件内容以清单SHA校验。

`CoopSync/research/upload_inventory_recommendations.md` 是此前建议取舍的材料；用户最终要求所有项目文件交接，本次采用完整保留，包含其建议排除的历史build、存档、安装包和原始日志。该旧建议不是本次实际上传清单。

第三方安装包、库和原有MOD保持原有归属；仓库未声称拥有其源码或改变其许可。MinHook的源文件与许可在DoorStep vendor目录。游戏本体需另行安装。存档、崩溃材料、截图和账户命名目录是原用户要求随项目保留的原始调查资料，不是当前电脑的游戏状态。

历史文档可能写“尚未安装新模块”或某PID正在运行，这是当时的结论。当前以STATUS、源码、实录生命周期和构建验证为准。
