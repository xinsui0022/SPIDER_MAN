# 同档单人对照

这是将选定来源的存档复制到普通游戏环境，完全关闭 MOD 后做单人对照，目的是区分存档状态与 MOD 运行时 Hook。默认使用 `SMT/Save`；也可使用当前普通存档。它不会修复或推进任务，也不能证明合作功能正常。测试时需要记录所选槽位：旧档重放与 MOD 菜单创建的新档应分别判断。

当前任务的过渡目标标记为 `DNoSave=1`，因此重启本身可能回到存档中的另一个阶段。先核对任务名、目标和所处阶段：只有重启前后阶段相同才可比较。若普通模式恢复标记但阶段也改变，不能单凭这一结果认定是 MOD 实时 Hook 导致；这可能同时受重启和存档回退影响。

1. 正常退出 Spider-Man 和 SMT-Launcher。准备和恢复都会检查这两个进程，仍在运行就停止。
2. 运行“准备同档单人对照.cmd”。助手先冻结并核验完整 `SMT/Save`，将普通游戏当前账户原档改名保留，再复制冻结副本到普通存档目录；最后改名本地 `winmm.dll`，完全关闭 SMT。原始 `SMT/Save` 不会被修改。
3. 准备成功后，手动直接启动游戏目录的 `Spider-Man.exe`，不带 `-mp`。不要使用联机 Launcher。选刚才出现问题的同一槽位，观察任务标记和地点触发；先不要开新任务或覆盖手动存档。游戏自身可能自动保存，对照结果会保留。
4. 正常退出游戏，运行“恢复联机环境.cmd”。助手将对照产生的普通存档移入此次诊断 session，恢复普通游戏原档与 `winmm.dll`。之后可照原方式启动联机 MOD。

## 用普通存档做对照

`baseline_control.py prepare --source native` 会冻结当前普通存档目录，完整保留原目录，再把冻结副本复制回普通存档位置并禁用 MOD。此模式不会导入 `SMT/Save`。如果当前目录仍是上一次测试导入的 MOD 存档，必须先退出游戏并恢复上次 session；助手也会拒绝叠加未恢复的测试。来源是运行准备时的当前普通存档，助手不会把旧备份目录自动当作来源。

从 PowerShell 运行（游戏须已退出）：

```powershell
& 'C:\Users\xinsui\AppData\Local\Programs\Python\Python311\python.exe' -B 'C:\Users\xinsui\Desktop\游戏\蜘蛛侠联机mod\序章修复调查\baseline_control.py' prepare --source native
```

默认的“准备同档单人对照.cmd”仍使用 `smt`，等同于 `prepare --source smt`，原有操作方式不变。两种来源共用原来的恢复命令，测试副本及产生的存档均保留。

每次准备生成独立的“同档对照_日期_时间_编号”目录，内含冻结副本、SHA256 清单、原档清单和逐步状态日志。`state.json` 记录来源类型、固定来源路径及测试目的；冻结副本分别位于 `frozen_smt_save` 或 `frozen_native_save`。所有存档都保留，不删除或覆盖原件。准备途中失败会尽可能回退；恢复中断后可再次运行恢复。若检测到原件变化、目录冲突或链接，会停止并说明原因。

命令行 `check` 和 `status` 仅检查，不创建文件。`prepare` 和 `restore` 不会自动启动游戏，也不注入 DLL、写游戏内存或调用游戏函数。
