# 客机 22:27 崩溃 RVA 的本机固定版本静态核对

范围：只读本机已核验游戏 EXE 与 SMT core，映射 root 提供的客机栈 RVA。客机 dump 的实际模块版本、寄存器与载入字节由另一个审计核验；本报告不把本机静态映射单独当成客机模块一致性证明。没有改游戏、存档、内存或 UI。

- 游戏 SHA-256：`e297d4d94f1ffe4febf289745e79e7b6fa233a788e7a00f480fc77c55db81ad1`。
- core SHA-256：`b7ab575100f2346af25180d74bf9641e24ce09bf549ce47446be09c3462606c7`。

## 故障是明确的图形设备错误崩溃分支

RVA `0x1CBBD80` 的12字节为 `c7 04 25 00 00 00 00 06 00 7a 88 c3`：

```asm
mov dword ptr [0], 0x887A0006
ret
```

这是显式向零地址写入错误码的独立叶函数，不是普通分配器返回空指针后读取对象。`0x887A0006` 在本机 EXE 的字符串中就是 `DXGI_ERROR_DEVICE_HUNG`，也与 [Microsoft 的 DXGI 错误定义](https://learn.microsoft.com/windows/win32/direct3ddxgi/dxgi-error) 相符。这解释了为何图形设备错误最后可能表现成 `C0000005`；它不直接证明图形设备挂起的底层诱因。

可见调用链与提供的栈地址吻合：

1. `0x18E275E` 调用设备虚函数后检查 HRESULT；失败分支 `0x18E2768` 向下记录 `g_RenderDevice.GetDevice()->GetDeviceRemovedReason()`。该字符串有明确 RIP 相对引用，位于 RVA `0x4E58AB0`，日志分类字符串为 `D3D`，格式为 `%s failed with HRESULT %u (0x%08x)`。
2. `0x18E27A3` 调用实现对象虚表 `+0x178`，返回地址正是栈中的 `0x18E27AA`。EXE 原始虚表对应目标为 `0x1CB8720`。
3. `0x1CB8720` 内部按对象模式重新查询设备原因，把结果存入 `r14d`；不是仅按来参 EDX 直接分派。随后 `0x1CB8A5E` 比较 `r14d` 与 `0x887A0006`，相等就到 `0x1CB8A94` 调用虚表 `+0x188`，返回地址正是栈中的 `0x1CB8A9A`。
4. 该虚表 RVA `0x4F35E38`，`+0x188` 指向 `0x1CBBD80`。Complete Object Locator / TypeDescriptor 的实际 RTTI 名为 `.?AVNxD3DImpl@nx@@`，支持 D3D 实现分类，不是猜测函数名。

更上层 `0x188F27F` 是一次虚函数调用后的返回位置，可见循环按返回值1重试、按0提取结果数据；`0x18963BD` 是调用回调后返回位置。没有依据将这些匿名函数命名成存档、分配器或具体资源读取函数。

`0x1CB8720` 入口确有“特定对象模式且 EDX 为 `0x8007000E`”的特殊处理，但**代码存在这个分支不代表本次 dump 走过它**。当前错误分派需用客机 dump 的设备原因 / `r14d` 核对。

## 旧本机 hook 记录的覆盖范围

旧代码差异快照是 PID37700，游戏 SHA 匹配本机，104个 patch region、541个差异字节。独立从原始 / 载入上下文字节重算，正好重现全部541个差异字节。给出的5个栈 RVA 均不在差异字节中；故障叶函数、`0x1CB8720–0x1CB8AED` 错误分派及其上层局部调用窗口也没有已记录的直接覆盖。

这只说明**旧本机快照没有直接改写这些代码窗口**；不能替代当前客机的载入字节核验，也不能排除 MOD 在别处、虚表 / 数据或其他注入的间接影响。

## 两次运行必须分开

本次真客机 dump 是 **22:27**。另一个 NIXXES 日志从 **22:31** 启动，**22:35** 的 GraphicsPipelineState / CreateHeap `0x8007000E` 属于后续运行，不能作为此 dump 的同次前置错误拼接。它可独立支持后续运行有资源创建问题，但不能证明22:27这次是内存不足。

当前可收窄为：**在匹配本机代码的前提下，该栈到达 D3D 设备挂起的主动崩溃路径；没有静态依据把它归为存档读写或普通 allocator 空指针。** 设备挂起的具体诱因、与 MOD 的因果关系仍需客机同次证据。优先核对 dump 的故障字节、设备原因值、同次22:27日志和实际图形设备上下文。
