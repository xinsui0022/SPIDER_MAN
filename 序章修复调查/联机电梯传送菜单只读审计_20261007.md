# 联机电梯临时绕行：只读菜单与回调审计（2026-10-07）

已确证当前 SMT v0.5.1 有对所选玩家的传送操作。优先可做的临时测试是：主机站在电梯门内的安全地面，打开 MOD 菜单中的 **PLAYERS**，选哥哥，选 **TELEPORT TO ME**。这是有实际按钮与执行回调支撑的功能；本轮未运行它，不能承诺客机电梯场景/碰撞状态一致，也不能将位置传送等同开门或检查点同步。

另一条已存在的操作是哥哥在 PLAYERS 选主机，再选 **TELEPORT**。不要猜 F 键；本轮没有恢复可靠菜单热键。若界面没有显示该项或操作后仍被挡，应记录结果并停止重复传送。

## 证据

- 本机核心与原发布包核心 SHA-256 相同：`b7ab575100f2346af25180d74bf9641e24ce09bf549ce47446be09c3462606c7`。
- 当前和原包 `SystemOverlay_UIv2.gfx` 相同：`f145698f9e9e751cc980f02f1abb13ab28c2b7cf96383e8db5167f1e4ec86b74`。
- UI `smt.elements::LobbyPlayerList/ButtonA`，method 1562，body FO `0x90aab`：打开所选玩家 `options`；确认 popup 选项时取 `command` 并携当前选中玩家数据调用 `ExternalInterface.call`（PC `0x3e–0x4a`）。因此不是装饰文字。
- Native 注册：RVA `0x66b0e→0x66b19` 注册 `SMT_TeleportToPlayer`；`0x66b35→0x66b40` 注册 `SMT_TeleportPlayerToMe`。Native 生成 `TELEPORT` 与 `TELEPORT TO ME` 对应选项及 command（`0x66fe5` 与 `0x6708c` 一带）。后者位于权限检查 `0x67057→0x6705e` 之后。
- `SMT_TeleportToPlayer` 捕获函数 vtable RVA `0x849a8`，invoke RVA `0x67ec0`。它解析所选 `handle`、寻找目标，直接将目标对象的 `+0x30/+0x34/+0x38` 三分量复制到本地对象同一字段（`0x67fa8–0x67fb6`）。符合到所选玩家的位置传送语义。
- `SMT_TeleportPlayerToMe` vtable RVA `0x849e0`，invoke RVA `0x67fe0`。它解析所选 `handle`，取本地玩家对象 `+0x30` 的12字节，调用 `0x29f90`，EDX 为所选玩家 handle，R8B 为 `0x16`，R9 为该12字节数据，栈参数长度 `0x0c`、标志1（`0x6807a–0x680b8`）。这是定向给所选玩家的实际消息调用，未在本轮独立确认客机接收应用。

## 局限及备选

本轮未确证“跟随主机”“手动同步检查点”或“只重播开门事件”的菜单。Preferences/Multiplayer 配置也无此开关。标准暂停“重新开始检查点”的具体客机同步语义没有确证，不能当成现成修复推荐。已有本机无客机重进同档保持 ELEVATOR_LOBBY 的验证，仅证明主机存档恢复，不能证明客机的门状态恢复。

若传送未成功，保留当前档案后，让哥哥在开门事件之前 JOIN，再由主机重新走该事件，是可区分“晚加入漏掉事件”的实验，但本轮未验证；不要用主线任务选择菜单重启整个任务代替有边界的检查点实验。

本审计仅读取文件和离线字节码/反汇编；没有操作 UI、进程、游戏、存档、配置或原安装包。完整指令片段见同名 JSON。
