## 解码方法与复用位置

1. 以小端读取文件头 `<4I>`：magic `0x44415431`（字节 `31 54 41 44`）、版本 8、文件长度、节数量。自文件偏移 `0x10` 起，每节条目为 `<tag:uint32, offset:uint32, length:uint32>`。
2. 相关 GameSaveFile 节 tag 为 `0xD436A987`。该节开始是 `GME2`，后面包含多个序列化对象，不能只解析第一个对象便宣布缺少 SaveFilename 或 PlayerLevel。
3. 序列化对象头为 `<zero:uint32, magic:uint32, child_count:uint32, data_length:uint32>`，对象 magic 为 `0x03150044`。每个子字段头为 `<name_hash:uint32, flags:uint16, unknown:uint8, node_type:uint8>`，随后是每字段一个 uint32 名称偏移。
4. 名称偏移针对整个 DAT1 文件，取该位置至 NUL 的字符串。元素数由 `flags >> 4` 得到；按头里的类型顺序读取字段数据，嵌套对象递归读取；对象数据末尾按 4 字节边界和声明 data_length 验证。相关类型包括 UINT8/16/32、INT8/16/32、FLOAT、BOOLEAN、STRING、OBJECT 与 INSTANCE_ID。
5. 主档 GameSaveFile 节起点为 `0xA4E0`，第一对象在 `0xA4E4`，含存档槽元数据的后续对象在 `0xA568`。`SaveFilename` 名称偏移 `0x61E` 在元数据对象名称表的引用位置是 `0xA75C`；`PlayerLevel` 名称偏移 `0x6F8` 的引用位置是 `0xA798`。使用属性名称定位后再解码，避免靠固定文件偏移猜测。
6. prefs 序列化节 tag `0x2EE91673`，起点 `0x310`。当前测试与保留普通 prefs 的输入相关嵌套对象都为：MouseControlNormal/Aiming 的 SensitivityFactorX/Y = 0.5，InvertX/Y = false。语义差异仅最近槽位、视角敏感度、字幕、提示记录和 NG+ 解锁，未找到输入禁用字段。

格式参考：[Overstrike 的 SerializedSection 源码](https://github.com/Tkachov/Overstrike/blob/main/DAT1/Sections/Generic/SerializedSection.cs)。本次使用最小 Python 只读解析器，没有加载或运行第三方游戏 DLL，没有用解析结果重新序列化存档。

### 原版后端对 OnInvalidSaveContinue 的静态依据

以下地址均为上述固定 SHA256 的 `Spider-Man.exe` 的 RVA，反汇编首选基址为 `0x140000000`。只读使用本机 objdump 和 PE 字段读取；没有执行这些函数。

1. `OnInvalidSaveContinue` 字符串在 RVA `0x389B360`；其唯一 RIP 相对引用位于函数 `0x7ACE80` 内的 `0x7ACEE3`。该函数构造保存数据并向 UI 分派这个事件。
2. 调用点 `0xC5D21C`：前面 `0xC5D1E9` 将全局对象 `0x70A53E0` 传给 `0xCE69E0`，`0xC5D1F5` 测试返回布尔；返回 false 才走向 `0x7ACE80`。另一个调用点 `0xC5E6DA` 也处于同一检查返回 false 的分支，但是否执行检查还受其入口参数控制。
3. 检查函数 `0xCE69E0` 的完整核心指令如下：

```text
mov rax, [rcx]
call qword ptr [rax+0x78]
cmp dword ptr [rax+0x28], 0
setge al
ret
```

4. `GameSaveFile` RTTI 对应虚表 RVA `0x38FCE40`，虚表偏移 `+0x78` 对应函数 `0xCE45C0`。该函数按当前模式 / campaign 选择对象内部的 `+0x20`、`+0x68` 或 `+0xB0` 数据块。CampaignSave 的静态反射名称表 RVA `0x4F99508` 第一项是 `CurrentLevel`；字段偏移表 `0x4F99478` 第一项为 `0x28`，后续为 CurrentCheckpoint `0x2C`、CurrentCheckpointId `0x30` 等。

这条分支的直接条件是**所选 CampaignSave 的 CurrentLevel 必须大于等于 0**。冻结 MOD 主档解码值为 -1，与进入 `OnInvalidSaveContinue` 分支吻合。不过尚未在对应调用时刻记录所选数据块和运行值，所以该档与分支的关联是强候选，尚非完整运行追踪。

菜单侧另有独立证据：原版 `OnInvalidSaveContinue` 转到难度选择时没有恢复输入许可，而 Continue 按钮路径已关闭许可；“加载游戏”入口则仍可用鼠标选择难度并进入开始面板。这解释了为什么同一副本两种入口可能在输入响应上不同，不能将两种现象都归因于引擎冻结。

**禁止从此证据推导直接把 -1 改为 0 的修复。** 原版新游戏同时建立了检查点、关卡和剧情初始化状态；只改一个字段可能使关卡、剧情脚本与恢复位置不一致。下一步应通过原版正常开始流程验证这个 0% NG+ 测试副本能否建立正确的序章恢复点，并观察等级 / NG+ 标志与任务触发。日志 type 3/code 2 的限制仍按上文执行。
