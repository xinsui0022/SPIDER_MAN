# 客机真实游戏崩溃：最小转储核验

只读输入为 `crash_2026-10-06_22-27-02.dmp`（954967 B）及同名 `.log`。未操作 UI、游戏进程或修改游戏、配置、存档。没有输出无关内存内容。

## 故障闭合

- Minidump 的 MiscInfo 记录进程 ID 为 **21480**，ExceptionStream 记录线程 ID 为 **19020**。
- ExceptionCode 为 `0xC0000005`；ExceptionAddress 为 `0x7FF654F0BD80`，对应客机 `Spider-Man.exe + 0x1CBBD80`。
- 两个异常参数为 `[1, 0]`：**写地址 0**。
- 转储在实际异常地址保存了 12 B 指令：`c7 04 25 00 00 00 00 06 00 7a 88 c3`。本机已核验游戏在相同 RVA 的 12 B 完全一致。
- 指令含义为 `mov dword ptr [0], 0x887A0006; ret`。这是独立的主动崩溃函数，并非由此即可认定的 JOIN 对象空指针解引用。
- 本机本版本 `0x1CB8A5E` 比较错误值 `0x887A0006`，相等则到 `0x1CB8A94` 调虚表偏移 `0x188`；返回地址正好是 **0x1CB8A9A**，吻合同名客机 crash log 的第 1 个调用帧。本机 SDK 头文件 `C:/TDM-GCC-64/x86_64-w64-mingw32/include/winerror.h` 第 3470 行将 `0x887A0006` 定义为 `DXGI_ERROR_DEVICE_HUNG`。

因此本次证据支持 **DXGI DEVICE_HUNG 错误处理路径主动触发游戏崩溃**。连接／载入是用户观察到的触发时机，但目前不能确定联机同步代码、GPU 驱动、渲染负载或其他条件中哪项导致设备挂起。

转储还包含 Windows 系统 winmm.dll（10.0.19041.3636），它与游戏目录代理是两个独立模块，不作混同比较。客机实际已加载 MOD 核心。

用于比对的本机文件 SHA256：游戏 `e297d4d94f1ffe4febf289745e79e7b6fa233a788e7a00f480fc77c55db81ad1`；核心 `b7ab575100f2346af25180d74bf9641e24ce09bf549ce47446be09c3462606c7`；代理 `ec59e8537eb9c6ec144897f64ccd8a79618309dd1bb3a62b65ad70b308bcab85`。

**元数据匹配不是客机完整文件哈希校验。** 本次故障地址处直接保存的相同指令，加上相同游戏版本、ImageSize、时间戳，支持在该故障及其已吻合返回点使用本机 RVA 映射；不能把它扩大为客机所有字节完全一致。

## 寄存器与线程栈限制

转储为 AMD64 架构。ExceptionStream 的 CONTEXT 长 1232 B、Flags 为 `0x10005F`，但其中 `RIP=0x7FFA2F33CC91`（ntdll.dll+0x4CC91）、`RSP=0xA1EA4FF820`，**不等于 ExceptionAddress**。该上下文的 R14、RBX 为 0，不能当作故障现场的 HRESULT 寄存器。

该转储有 108 个线程。对异常线程当前 RSP 附近的保存栈内容核验，没有重建出同名 crash log 的完整故障调用链，因此不将这些原始模块地址候选冒充已展开的故障栈。故障调用链采用同名 crash log：`1CBBD80 → 1CB8A9A → 18E27AA → 188F27F → 18963BD → BaseThreadInitThunk → RtlUserThreadStart`，并用上面的异常指令与直接返回点验证其关键部分。

## 必须分开的运行记录

附带 NIXXES 游戏日志是 **22:31 新启动** 后到约 22:35 的另一次运行，出现 `0x8007000E / E_OUTOFMEMORY`。它晚于本次 22:27 转储，不能合并成同一次事故，不能仅据此把本次 DEVICE_HUNG 改判为内存不足。

主机上更早核验的 `crs-video.exe.43512.dmp` 则是另外一个进程在代理中读内存失败，也不能替代这次客机 `Spider-Man.exe` 的故障证据。
