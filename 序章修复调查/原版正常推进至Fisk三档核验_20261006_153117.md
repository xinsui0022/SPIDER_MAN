## 未解码区块与结论边界

`0xD0A9DF` 三份均 23672 B：de29… 与 ae646… 逐字节相同；原版 a836… 只改变四处各 8 B，共 32 B，字段语义未确认。`0xA806F448` 在原版 ae646… 与 a836… **逐字节完全相同**，均 23780 B；MOD de29… 为 23672 B。因此不能将“该区块没有随剧情变化”当作恢复失效证据，也不能仅按 MOD 区块减少 108 B 判定丢失场景。`0xC0174D02` 为 5540 / 4964 / 5380 B，尚未确认其语义。MSFX 为 12254 / 12254 / 13046 B，原版增加 792 B 正好对应活动表从 11 项变为 29 项的两份记录增长。

本轮证明原生初始化档在无 MOD 时能够正常推进至 Fisk，并生成后续任务与新检查点；它还没有单独证明退出后能正确恢复，当前同档重载由 root 继续核验。若这份 Fisk 档重载成功，可提供一个已验证后续检查点，但仍不能代替相同街头阶段的归因对照。若需进一步锁定问题，区分力最高的下一项仍是原版在 `SECOND_STOP_FINISH` 精确保存、退出、重载，再与 de29… 对比；目前没有这份精确阶段快照。
