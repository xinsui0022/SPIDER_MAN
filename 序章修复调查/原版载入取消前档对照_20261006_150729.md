## 保存结果

- **MSFX 两份完整目标表没有变化。** 相对 `0xDCB` / 步长 24 B、`0x2E98` / 步长 20 B 的 11 项目标 hash、全部原始字、顺序均完全相同；状态均为 `[2,2,2,2,2,2,2,2,2,1,0]`，即运行顺序中的 `SECOND_STOP_FINISH` 仍为 1、`GET_TO_FISK` 仍为 0。MSFX 全 section 始终 12254 B，仅相对 `0x54C` 的一个字节从 00 变为 01；它位于序章全局任务 hash 之后第 13 字节，尚未确认这个字节的含义。
- **Segments 阶段没有变化。** `GP_A1_SWING_TUTORIAL_SECOND_STOP_FINISH` 仍在；Duration 从约 7.3624 增至 32.8322，其他已有计时增加约 25.47 秒；本次 GameSegment ID 替换上次 ID。没有观察到新后续任务阶段。
- **恢复元数据没有修正。** `0xD436A987` 全部可解析反射字段仅 LastSaveTime 从 2125083096 变为 2125083604。CurrentLevel=0、checkpoint=3959482847、checkpointId=10548525917104244791、LastPosition=(1107.189697,45.762451,1288.171997)、ActiveMissionHash=0x3705D72B、TotalPlayTime=0、50级 NG+ 都与输入相同。
- `0xD0A9DF` 始终 23672 B，仅相对 `0x44E9`、`0x5B35`、`0x5B5A`、`0x5B7F` 四处各 8 B 改变，共 32 B；头部与计数字 429 相同。未确认这四个字的语义，不能宣称该区块代表的场景状态被清空或完整正确恢复。`0xA806F448` 始终 23672 B，**逐字节完全相同**。
- 其他反射变化为保存时间 / 使用计数等：`0x9D1B37DC` 900→956 B，若干 Entries.SaveTime / UseCount 更新。`0xC0174D02` 4964→4644 B，未确认其区块语义，不能称长度减少就是任务脚本丢失。其余若干区块只改变序列化字节，可解析反射字段没有改变。

## 能支持的结论与边界

用户实际确认原版载入仍无任务提示，加上本轮来源 hash、两个目标表和重存结果，支持：**取消前这份文件的无提示现象，在不加载 MOD 的情况下仍可复现；原版载入后退出 / 重存没有自动修正存档内的阶段与恢复信息组合。** 它不是本轮原版载入时把 11 个目标删除了，也不能解释成误用了后来取消后的存档。

这不能证明只有 HUD 隐藏，不能证明目标触发器正在正常工作，也不能证明具体 MOD hook 或哪个保存区块导致问题。当前 checkpoint 不变本身仍不够判定错误，因为原版可能在多个教程阶段共用检查点。存档检查不能替代运行中的场景、脚本及任务触发核验。

## 下一项有区分力的对照

从已验证的原生初始化档 `ae64678c…` 出发，**全程关闭 MOD**，在原版推进到相同 `SECOND_STOP_FINISH` 阶段（完成最初摆荡与前几段战斗），保留退出前保存快照，然后正常退出、重进相同设定档，核对任务提示和推进，比较相同 MSFX / checkpoint / D0A9DF 区块。若原版产生的同阶段档能恢复，而当前 `de29…` 不能，才进一步支持 MOD 运行期间生成的恢复状态组合有差异；若原版同样不能，则应检查序章重载流程或基础游戏问题，不能将原因直接锁定 MOD。
