# 接手说明

更新于 2026-10-11。这个目录是蜘蛛侠联机模块的开发成果目录；目前还没有可玩的双人联机补丁。

## 已经做出的成果

`src/` 是源码，`build/CoopSync.exe` 是可以在本机启动两个进程、通过真实 TCP 通信的协调原型。它已处理双方准备、统一开始、任一方请求跳过、双方结束确认及断线等情况。目前运行时必须显式使用模拟模式，游戏动作由模拟输入提供。

`src/game_adapter.*` 是游戏接入校验桥，真实游戏后端仍未实现。`research/` 中保存了过场及跳过 UI 的静态研究和只读采样器；`logs/` 保存测试与真实进程观察。完整进度见 `PROGRESS.md`，构建与运行方法见 `README.md`。

新增 `build/CoopSyncRuntime.dll`：自主原生观察模块，已在游戏 PID17652 完成真实加载、350样本菜单采样及正常停止。随后重新启动记录“救助平民”关卡，已找到门/血量组件和动态过场字段。它只读取游戏对象，没有执行门操作、修改血量或开始/跳过剧情。加载说明见 `RUNTIME_INTEGRATION.md`。

## 要实现的联机行为

双方能从普通新游戏开始合作。主机决定场景、门与碰撞、敌人及任务状态；客机跟随同一个世界。剧情触发时先召集另一位玩家，确认双方场景加载完成，再共同进入剧情；任意一方跳过，双方都正常退出剧情并完成相应任务收尾。任务奖励、升级资源及合作存档也需要单独接入和验证。

现有 SMT 作为研究参考，不限定新模块的实现。网络消息或任务摘要相同，不能代替门、碰撞和敌人实际一致。

## 这次人工测试

用户刚接手此前兄弟的工作。最初报告处于主菜单或未打开游戏，随后选择“继续”进入关卡，确认任务提示为“阻止倒数”。菜单期间读到的任务数据可能是保留状态，不能由此判断已进入场景。

先按游戏提示完成“阻止倒数”。出现过场后播放两三秒，有跳过提示就用游戏原生操作跳过；没有提示则自然播完。恢复操作后暂停，并报告是否出现过场、是否实际跳过、下一步任务。记录器就绪前不开始专门的过场测试。

本次三路探针只读游戏进程，没有安装模块、调用游戏函数或写入存档。日志目录的 `manual-skip` 标签是测试意图；是否实际播放或跳过，要结合人工报告与原始记录核对。

本轮已完成：用户确认剧情无跳过选项、自然结束、恢复战斗并通过机房出口；后续又报告另一段剧情同样无跳过选项。两轮联合采样均正常退出，没有验证手动跳过。完整24文件快照已保存在 `logs/door_native_current_20261010_0901_audit/save_snapshot/`，后续检查点确实已落盘。保存重进仍待验证；本次测试档为50级NG+，不代表普通新档已经支持合作。

## 门故障的状态

此前电梯门问题在完整回退较早存档后有局部恢复证据。后续机房出口的坏档在关闭 SMT 后仍失败，初始原因尚未证明；正常存档在同阶段推进、保存和重载的对照仍需补完。客机门与碰撞不跟随主机是另一个世界同步缺陷，也还没有修复。
