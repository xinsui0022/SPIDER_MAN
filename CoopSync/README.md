# CoopSync 0.1 开发原型

这是为《Marvel's Spider-Man Remastered》自主开发的双人合作同步模块。当前完成原生 Windows 协调器、二进制协议、实际 TCP 通信与已在游戏中验证加载的自主只读 DLL。

**当前尚未接入游戏内过场控制，不能用它一起过剧情或打怪。** 可执行文件只在明确指定 `--simulate` 时运行；没有该参数会拒绝执行。测试里的过场与世界结果为模拟输入，真实网络收发发生在独立进程之间。

## 成果位置

- `src/`：主机权威状态机、通信协议、Windows TCP 和模拟入口源码。
- `build/CoopSync.exe`：已编译的原生通信验证程序；不是放入游戏目录的插件。
- `build/CoopSyncRuntime.dll`、`src/runtime/`：已在真实游戏中加载验证的原生观察器，记录过场/任务/门/血量原始数据。
- `RUNTIME_INTEGRATION.md`：原生构建、加载与停止方法、真实证据和能力限制。
- `tests/`：协调器、协议、真实 TCP 集成与异常会话测试源码。
- `logs/integration_summary.json`、`logs/session_fault_summary.json`：本机真实两进程通信与异常消息测试结果。
- `tools/observe_game.py`：只读观察当前游戏任务；不注入、不写游戏内存、不调用游戏函数。
- `research/`：可重复的过场接口静态定位脚本和证据；未知地址不用于执行。
- `research/cinematic_runtime_probe.py`：只读核验过场管理对象；本轮已在真实原版进程核验两处对象身份。
- `src/game_adapter.h/.cpp`：抽象游戏后端与校验桥；真实游戏后端尚未实现。离线测试显式隔离假后端。
- `record_runtime.cmd`、`tools/record_runtime.py`：同时记录任务、过场组件和原生跳过 UI 的只读状态。
- `ADAPTER_CONTRACT.md`：后端证据、游戏线程实例重查和准备/结束屏障要求。
- `DEVELOPMENT_CONTRACT.md`：协议、状态机与后续游戏适配约定。

## 已实现的协调规则

主机决定本次剧情及场景版本，等待双方就绪后共同开始。任意一端请求跳过，都由主机统一传播；准备阶段的请求排队到双方开始之后。已结束的端不再收到跳过操作。双方结束结果相同才恢复；不同、断线或等待超时则停止推进。

每次剧情独立编号，旧剧情消息不影响下一段；当前会话、消息次序、剧情票据和指令角色均校验。接收消息大小有上限，分包和部分收发正确处理，网络错误终止连接。

结束摘要目前仅为屏障输入。它不携带门、敌人、脚本或检查点数据，不能把摘要一致当作这些状态已经复制。

## 本轮验证

- 16项协调器测试通过，包括双方就绪、任意一端跳过、准备阶段跳过、结束先后次序、旧消息、重复请求、矛盾结果、断线和超时。
- 186项协议/TCP检查通过，包含完整字段、每个截断位置、非法帧、分包超时保留、断连和发送期限。
- 5种本机两进程场景通过：自然结束、主机跳过、客机跳过、结果不一致、客机断线。后两项正确停止推进。
- 10种异常会话测试通过：未准备先开始、错误剧情编号、提前释放、错误会话、序号断层、开始前跳过、错误剧情票据、客机越权指令、过长和截断帧。
- 未实现游戏适配时明确拒绝执行的检查通过。
- 只读观察器自检通过；先记录游戏未运行，随后已附加真实原版进程，读取到费斯克机房倒计时任务。输出仍明确标记场景就绪和完整世界摘要未验证。
- 真实原版进程中的两个过场管理对象与静态定位的vtable匹配；仅证明对象身份，开始、跳过和结束调用尚未验证。
- 新增14项游戏适配桥离线测试通过，涵盖真实证据缺失、实例变化、操作前二次检查、结束与跳过竞态，以及任务摘要不能冒充完整场景状态。输入均来自明确的假后端。
- 过场采样器15项纯模拟内存自检、跳过UI采样器9项自检、记录分析器11项合成轨迹检查通过。
- 新增31项UI原始证据分析/假录制校验通过，已加入 `validate.cmd`；原始回调、标志和计时变化均不会自动被标成可调用或已跳过。
- 权限恢复后，已对PID25612运行三路联合只读基线：任务仍为机房倒计时；过场静态对象和跳过UI双虚表核验通过。原生跳过回调槽此时为零，未执行过场播放或跳过测试。证据在 `logs/runtime_three_observers_20261010/`。

基线还发现组件选取槽会在零与同一个指针之间变化，部分样本读取期间发生变化。记录器保留原始证据并标为有歧义；不能把选取槽非零当作正在播放，或把归零当作剧情结束。

上述协调验证来自本机独立进程。另一台电脑、真实游戏内双端过场、场景门/碰撞复制、敌人伤害同步和合作保存仍未验证。

随后完成两轮各300秒的原版只读实录，任务从机房倒计时推进到下一段。用户确认剧情无跳过选项、自然结束、机房出口可通过；完整24文件备份证实后续检查点已保存。原生回调槽在两轮各2982个UI样本中均为零，未验证手动跳过。当前存档重载、真实游戏内双端同步以及门/敌人的复制仍未验证。详细接手说明见 `接手说明.md`，证据见 `logs/runtime_manual_skip_20261010_in_game/` 与 `logs/door_native_current_20261010_0901_audit/`。

## 下一次过场采样

录制工具只观察已经运行的游戏，不启动游戏、不调用开始或跳过函数。任务以1秒间隔记录，过场组件和UI槽以100毫秒间隔采样；每次最长5分钟，输出目录独立创建，避免覆盖旧记录。

```powershell
& $env:ComSpec /d /c 'record_runtime.cmd --seconds 120 --label natural-end'
& $env:ComSpec /d /c 'record_runtime.cmd --seconds 120 --label manual-skip'
```

两条命令用于两次分开的测试，不应同时运行。先等控制台报告三个观察器均有基线，再在同一短过场分别自然播放结束与使用游戏原生操作跳过。`--label` 只记录测试意图，不能证明跳过已经发生。

每次产生 `manifest.json`、`cinematic.jsonl`、`missions.jsonl`、`ui_skip.jsonl`、统一接收时间的 `timeline.jsonl`、错误输出和 `analysis.json`。分析报告原始组件选取、任务子集及稳定UI槽/原始计时变化，始终不将它们标成已验证的跳过、场景就绪或世界同步。

## 编译和复现（开发用）

2026-10-12 交接更新：构建/验证/录制入口已支持发现本机 MSVC、Python，探针支持 Steam 安装发现及 `COOPSYNC_GAME_EXE` / `COOPSYNC_OBJDUMP`。依赖见 `requirements.txt`，完整说明见 `CONFIGURATION.md`；下面的原机路径描述保留为历史记录，当前以脚本为准。使用父仓库完整克隆，以保留任务观察 helper。

本机 `build.cmd` 使用已有 `C:\D\VS_2022` x64 C++ 工具链，C++17、静态运行库、`/W4 /WX` 编译。`validate.cmd` 构建并执行全部当前测试，使用本机已有 Python 3.11。在其他开发电脑需调整这两个脚本的工具路径；通信程序本身不依赖Python。

```powershell
& $env:ComSpec /d /c 'validate.cmd'
```

手动观察一个通信场景时，在两个终端分别运行：

```powershell
.\build\CoopSync.exe host --simulate --port 17637 --scenario guest-skip
.\build\CoopSync.exe guest --simulate --host 127.0.0.1 --port 17637
```

默认只监听本机；显式 `--bind` 可指定监听地址。第一版地址限定数字IPv4/IPv6，连接不触发DNS。本轮没有修改防火墙，也没有做跨电脑连接测试。

## 后续实际游戏接入

先闭合客机召集、实际场景/演员就绪、过场身份、正常开始、用户跳过和正常结束入口。随后在同一短过场验证召集→双方就绪→共同播放→任意一端跳过→任务和世界终态一致；同时开发门/碰撞与同一敌人的主机同步，再验证普通新档和保存重进。

目前静态定位的 `Cinematic2` 类型和命令分发链是研究基础，真实对象实例、线程约束与用户跳过路径尚需核验。不能按函数名称直接调用未知地址。

游戏安装文件、现有插件加载配置和玩家存档没有由工具修改。2026-10-11 已临时加载自主只读 DLL 到游戏内存；SMT 仍未恢复。过场控制及门/敌人同步尚未接入。
